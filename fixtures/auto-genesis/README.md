# auto-genesis fixtures

Two adapters that pin the two halves of `riptide sim generate`'s tick-0 genesis
classification. They exist to make the boundary between "codegen can stand this
up" and "codegen must not guess" testable, not to model any real protocol.

| Fixture | Classification | What it pins |
|---|---|---|
| `derivable/` | `genesis: "derived"`, `gaps: []` | A wired `init` that a real program accepts: funded persona actors, an adapter-declared PDA, and an address-unconstrained account. |
| `gaps/` | `genesis: "gaps"` | One unresolved seam per refusal class, each with a stable `kind` and a `marker` that literally appears in the file it names. |

`riptide sim generate` writes its verdict to `.riptide/sim/setup-gaps.json`
(`schema_version: "setup-gaps.v1"`). An empty `gaps` array means derived; a
missing file means the crate was generated by a CLI older than that schema.

## `derivable/`

`program/` is a ~190-line raw-Borsh program, chosen so every genesis fact is
declared rather than inferred:

- **No Anchor account discriminators.** The IDL declares plain `fields`, so a
  zero-initialized allocation at the declared `space` is a legitimate starting
  state instead of bytes the program would have written itself.
- **`ledger` is a program-checked PDA.** The program re-derives
  `[b"ledger", authority]` and rejects any other address, so the address genesis
  derives from the adapter's `pda` seeds is provably the one the program demands.
  A genesis that guessed would fail loudly here.
- **`treasury` is address-agnostic.** The program asserts owner and length only.
  This is the other half of the derivable class: nothing constrains the address,
  so genesis derives a stable one under its own `riptide-genesis` namespace.
- **Real failure modes.** `withdraw` on an unbound ledger returns `IllegalOwner`,
  so a run produces honest error outcomes rather than a flat pass.

### Building the program

The `.so` is **not committed**: an unreviewable binary is weaker evidence than
source plus the exact command that produced it. Build it with the repository's
pinned Solana toolchain:

```bash
cd fixtures/auto-genesis/derivable/program
cargo build-sbf
```

`cargo build-sbf` writes `target/deploy/contribution_pool.so`; point
`program_so` in `adapter.toml` at that path if you build this way.

On a host that has the Solana platform-tools Rust toolchain registered with
rustup but no `cargo-build-sbf` binary, the equivalent direct invocation is:

```bash
cd fixtures/auto-genesis/derivable/program
RUSTUP_TOOLCHAIN=1.89.0-sbpf-solana-v1.52 cargo build --release --target sbpf-solana-solana
```

which is the path `adapter.toml` currently declares
(`program/target/sbpf-solana-solana/release/contribution_pool.so`). The two
outputs are not guaranteed byte-identical; `cargo build-sbf` is the supported
command and the one to prefer when it is available.

`program.json` pins `address` to
`HGRekLYd2arFZFL3BiyHRjTHhJk8fA9RamYDtcjiRsAV` (`sha256("riptide auto-genesis
contribution pool")`) so the program loads at a fixed id and every derived
address is reproducible without a keypair file.

### Running the smoke

```bash
riptide sim generate --adapter fixtures/auto-genesis/derivable/adapter.toml
(cd .riptide/sim && cargo build --release)
riptide sim run .riptide/sim --iterations 1 --flows 4 --seed deadbeef --out .riptide/sim/artifacts/smoke
```

Build from inside `.riptide/sim`: the generated crate pins its own
`rust-toolchain.toml`, and `cargo --manifest-path` from the repo root resolves the
outer toolchain instead, which silently builds the whole dependency tree twice.

The CLI test suite runs this automatically when the `.so` is present and skips it
with the reason above when it is not — so a green `npm test` on an unbuilt
checkout does **not** include the smoke.

## `gaps/`

`gaps/` has no program and is never executed: the classifier reads the IDL. Each
declared account fails for a different declared reason.

| Seam | `kind` | Why codegen refuses |
|---|---|---|
| `accounts.collateral_ata` | `decoded_account` | SPL token layout — mint, owner, and balance at tick 0 are a scenario choice. |
| `accounts.deposit_receipt` | `self_initializing_account` | Anchor-discriminated; the program writes the first 8 bytes itself. |
| `accounts.fee_sink` | `unresolved_account` | Not declared under `[accounts]`, not the signer seat, not a well-known program. |
| `accounts.price_feed` | `literal_address` | Address is reproducible; its bytes are not. |
| `accounts.vault` | `program_constrained_address` | IDL constrains the address to a PDA the adapter does not declare seeds for. |

`token_program` resolves as a well-known program and is deliberately **not** a
gap — the fixture asserts that too, so the classifier cannot pass by refusing
everything.

## What these fixtures do not establish

A derived genesis is a *baseline* starting state built from declared adapter
facts. It is not a reconstruction of a protocol's real launch conditions, and a
green smoke run is simulation evidence for that declared setup — not audit
signoff, coverage, or a safety claim about the program.
